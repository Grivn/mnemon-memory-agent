# 主、副 DSH 的 token 与 API 费用复核

2026-09-23。复算最终 v5 的九个实验臂，共 153 次主 DSH 回复；没有重新调用模型。本报告使用 API 返回的 usage、原始决策轨迹和 DSH 持久化事件，按当日官方公开单价估算费用，不是账户账单。

持续整理确实减少了主模型输入，但在本次 DeepSeek Flash 配置下，尚未让整套系统比 all-candidates 更便宜。原始布局中，主模型费用下降 85.5%，加上副本后总费用却是 all-candidates 的 2.80 倍。相比旧按需策略，新策略的总费用降低 15.0%；分散布局降低 18.1%。

## 计价依据与口径

价格查询日期为 2026-09-23，以下均为 **美元 / 百万 token**。主模型请求名为 `deepseek-flash`，官方当前对应 DeepSeek-V4.1-Flash；副本实际响应版本为 `jev-1.13.0`。

| 模型 | 未命中缓存的输入 | 命中缓存的输入 | 输出 |
|---|---:|---:|---:|
| DeepSeek Flash，低峰 | $0.150 | $0.003 | $0.600 |
| DeepSeek Flash，高峰 | $0.300 | $0.006 | $1.200 |
| JEV | $0.042 | 无单列价格/usage 桶 | 免费 |

DeepSeek 的工作日高峰为 UTC 01:00–04:00、06:00–10:00，即北京时间 09:00–12:00、14:00–18:00，中国法定节假日除外。最终实验全部发生在 9 月 23 日 UTC 00:05–00:17，逐请求时间戳均落在低峰；因此本报告主结果采用低峰价。[DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/?push_animated=1&show_loading=0&theme=light&webview_progress_bar=1)

JEV 官方公布输入 $0.042 / 百万 token、输出免费。响应中的 `output_tokens` 仍作为使用量列出，但不加入费用；不能把它当成普通 LLM 的收费输出文字。[TypeSafe 官方发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

主 DSH 的 usage 已被官方适配器映射成互斥桶：`inputTokens` 是未命中缓存的输入，`cacheReadTokens` 是缓存输入。两者相加才是上下文的输入总量。本轮没有独立缓存写入桶，不能把未命中输入再重复收取一笔“缓存写入费”。主模型关闭 thinking，未记录单独的 reasoning token，不另行叠加推理费用。[DeepSeek usage 定义](https://api-docs.deepseek.com/api/create-chat-completion/)

```text
主 DSH 费用 = (未缓存输入 × 0.150 + 缓存输入 × 0.003 + 输出 × 0.600) / 1,000,000
副 DSH 费用 = JEV 输入 × 0.042 / 1,000,000
总费用 = 主 DSH 费用 + 副 DSH 费用
```

后台调用与预热均计入，不计入此前开发轮次、网页验证、服务器、存储、免费额度、税费或实验结束后的后台运行。九个实验臂合计：主模型 **$0.061300**，副本 **$0.290625**，总计 **$0.351926**。这是最终对照实验的估算，不是此前全部研发花费。

## 实际 token 分类

每行均为 17 次用户输入及对应已记录的后台工作。连续整理行包含首次输入前的九轮预热。原始、分散布局分别在 12 个场景会话中运行；连续消融把 17 个输入串成一个会话，不应跨布局直接比较费用来判断策略优劣。

| 实验 / 策略 | 主输入未缓存 | 主输入缓存命中 | 主输出 | 副本 JEV 输入 | 副本 JEV 输出（免费） |
|---|---:|---:|---:|---:|---:|
| 原始 / all-candidates | 136,171 | 48,384 | 1,189 | 0 | 0 |
| 原始 / 旧按需策略 | 19,326 | 10,624 | 1,105 | 1,583,063 | 105,257 |
| 原始 / 持续整理 | 15,378 | 13,952 | 1,236 | 1,344,449 | 101,328 |
| 分散 / all-candidates | 116,126 | 41,344 | 904 | 0 | 0 |
| 分散 / 旧按需策略 | 15,966 | 8,576 | 758 | 1,582,828 | 97,184 |
| 分散 / 持续整理 | 11,946 | 9,984 | 670 | 1,300,094 | 97,552 |
| 连续 / JEV 整理 | 16,213 | 134,912 | 1,106 | 663,110 | 58,774 |
| 连续 / 本地预读 | 14,451 | 122,240 | 1,210 | 222,765 | 21,900 |
| 连续 / 关闭后台整理 | 15,823 | 126,208 | 1,058 | 223,342 | 21,846 |

原始布局主输入总量从 184,555 降到 29,330，减少 **84.1%**；分散布局减少 **86.1%**。但是 JEV 的输入量包含反复评估时重复发送的对话、候选和问题定义，不代表读到了同样数量的独立记忆。

连续 JEV 整理的主输入总量为 151,125，其中 **89.3% 命中缓存**。平均每轮上下文输入虽达 8,890 token，未缓存输入只有约 954 token。这解释了为何连续会话主输入增长明显，费用却仍只有 $0.003500。缓存降低计费，并没有缩短上下文本身或解决历史持续增长。

记录不能精确把主输入 token 再拆成“聊天、记忆、系统提示”三部分，也没有每插件独立账单；JEV 的一次请求会包含多个来源。字符数和来源比例不能充当精确的 token 计费分摊。

原始布局的新策略中，**94.8% 的 API 费用来自副本**。虽然 JEV 单个未缓存输入 token 比 Flash 低峰便宜约 3.57 倍，但它处理了更多输入，而且 Flash 的缓存输入比 JEV 公布的输入价还便宜 14 倍。压缩主上下文，并不自动意味着节省总 API 费用。

all-candidates 仍是最多 63 条公开窗口结果，不是 900 条全文全部注入。原始布局它的答案关键词命中是 23/34，新策略是 31/34；分散布局分别为 0/34、20/34。费用比较必须与能力差异一起看；这些关键词指标也不是完整回答正确率。

## JEV 费用花在什么时机

“前台”按实际发布给当前主回复的 Candidate 所属副本 turn 识别；其余已结算调用列为回复后工作。旧策略也处理助手更新，但其回复后工作不是新策略的增量 nap。预热另列，避免重复计入。

| 实验 / 策略 / 阶段 | JEV 调用 | 输入 token | 输出 token | 费用 |
|---|---:|---:|---:|---:|
| 原始 / 持续整理 / 前台 | 81 | 697,054 | 45,452 | $0.029276 |
| 原始 / 持续整理 / 回复后整理 | 66 | 647,395 | 55,876 | $0.027191 |
| 分散 / 持续整理 / 前台 | 78 | 657,368 | 41,676 | $0.027609 |
| 分散 / 持续整理 / 回复后整理 | 66 | 642,726 | 55,876 | $0.026994 |
| 连续 / JEV 整理 / 初次预热 | 25 | 229,433 | 19,366 | $0.009636 |
| 连续 / JEV 整理 / 前台 | 34 | 225,015 | 21,990 | $0.009451 |
| 连续 / JEV 整理 / 回复后整理 | 28 | 208,662 | 17,418 | $0.008764 |

连续会话的 **初次预热 + 回复后整理** 占副本费用的 **66.1%**，前台占 33.9%。这两类后台工作是后台费用的主体，不能因它们发生在回答之外而省略。

连续 JEV 版比本地预读版多花 **$0.018734 / 17 次**，总费用约为 **2.48 倍**，对应上一轮报告中多送达 4 组必要证据、多命中 4 项答案关键词的收益。三臂前台都是每次输入两次 JEV 决策。

若只从账面扣除一次预热，JEV 版这 17 次的主副合计为 **$0.021715**，仍是本地预读的 **1.72 倍**。这不是重新运行“无预热 JEV 策略”的结果：扣除费用后的结果仍享受了实际发生过的预热。

原始布局的新策略有 12 次冷启动、5 次后续输入，其前台调用多于连续消融。原始布局按决策阶段拆分如下，显示后续优化的主要位置：

| 阶段 | JEV 调用 | 输入 token | 占副本输入 / 费用 |
|---|---:|---:|---:|
| 后台原文片段整理 nap | 66 | 647,395 | 48.2% |
| 多步探索 explore | 32 | 431,041 | 32.1% |
| 最终正文筛选 leaves | 20 | 149,976 | 11.2% |
| 分组覆盖选择 cover | 12 | 83,506 | 6.2% |
| 检索词选择 terms | 17 | 32,531 | 2.4% |

百分比独立四舍五入，可能不恰好相加为 100%。完整各臂阶段明细和逐输入费用见 `cost-summary.json`。

## 放大尺度与收支平衡

如果按本次会话组合、缓存命中比例和预热频率原样重复，折算每 1,000 次输入：

| 请求组合 | API 费用 |
|---|---:|
| 原始 / all-candidates | $1.25 |
| 原始 / 旧按需策略 | $4.12 |
| 原始 / 持续整理 | $3.50 |
| 连续 / JEV 整理，按每 17 次重复一次预热 | $1.84 |
| 连续 / 本地预读，同样前台算法 | $0.74 |
| 连续 / 关闭后台整理，同样前台算法 | $0.75 |

这只是按实验组合归一化，**不是单个会话持续聊 1,000 次的预测**。真实长会话的历史增长、缓存、内容变化和整理频率都会变化。第一次预热可能被更多输入摊薄；实验结束后的无人输入维护也没有被本次记录覆盖。不能把后台轮询间隔直接乘以平均 JEV 调用费用来推算每日开销，因为检查没有变化时可能不发模型请求。

原始布局主模型节省 **$0.018194**，但副本用了 **$0.056467**。在保持当前主模型 token 与缓存结果不变时，收支平衡允许的 JEV 输入预算约为 **433,192 token / 17 次**，当前是 1,344,449；约需减少 **67.8%**。分散布局对应约减少 **71.0%**。这些是目标预算，不保证压缩到该预算后质量还能保持。

即便在原始布局的账面上完全扣除后台费用，只留下实测前台 JEV 和主模型，也仍是 all-candidates 的 **1.52 倍**；分散布局为 **1.65 倍**。因此只限制后台频率还不足以实现当前 Flash 配置下的成本反超，也需要降低前台多步探索的重复输入。这个减法同样不代表关闭后台后的实际质量或后续调用量。

后续值得按实际价值分别优化：

1. 前台减少没有新增证据的重复判断，复用可验证的导航，保留复杂问题所需的探索预算。
2. 后台按变化量和待整理量合批，而不只依据新回复次数启动语义整理；给预热和日常维护分别设置费用预算。
3. 继续同时报告主模型缓存、记忆覆盖、答案质量和用户等待；更换昂贵主模型时可重新核算，但不能据此预先宣称收益。

## 复核与复现

新增脚本离线重算九个压缩轨迹，交叉检查 153 次主请求的 usage 与持久化助手事件；用真实发布 turn 区分前台与回复后决策；核对预热、模型版本、重复决策、API 错误、全部 token 总量和低峰时间戳。费用另用 Python Decimal 独立重算，九行一致。不需要重跑 API 实验。

```sh
node scripts/summarize-jev-costs.mjs
```
