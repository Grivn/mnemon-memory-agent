# 阶段 3 补充报告：JevAgent 的 View 规则，用公式替代手调参数的尝试

日期：2026-09-26 · 分支：`codex/jev-replica-practice`（本地提交，不发布、不推送）· 模型：DeepSeek 作答、规划、判分，与 S5h 相同 · 预注册：`phase03-preregistration-20260925.md` 补充 5–7

## 结论

1. **LoCoMo 分数上不去，一半不是检索问题。** JevAgent（S5h）在 LoCoMo 上错了 160 题。
   - 约一半的错题，证据已经全部进了 View，模型仍然答错。其中 29 题回答"未提及"；104 题在三个方案里都答错，不少是标注有争议。
   - 另一半是检索问题，JEV 自己看得出来：JEV 给的最高分低于 0.5 的题占 20%，准确率只有 72.5%（其余题 93.9%），却包含了一半以上的错题。当时检索循环和 View 都没有用上这个信号。
2. **阶梯规则有效，已采纳并实现（`unsureFill`）。** 规则是：JEV 对所有候选都判"不需要"时，按它的排序填满 View（16 条，不设分数下限）；其余情况 View 不变。
   - 重放结果：LoCoMo 中这类题从 71.5% 升到 76.1%（+21 / −7，p = 0.013），折合全集约 +0.9。LongMemEval +5 / −2，没有退步。
   - 有把握的题放宽没有收益（+18 / −24），所以不动。
   - 真实重跑（S6 对 S5h），两个数据集的整体差异都在波动范围内：
     - LoCoMo：89.4 对 89.5（+39 / −41）。规则起作用的 324 道没把握的题上，72.5% → 74.4%（+23 / −17，p = 0.43），方向与重放一致，但不显著。
     - LongMemEval：90.0 对 91.8（+10 / −19，p = 0.14）。
     - 在规则没有改动的有把握题上，两次运行之间也分别差了 40 题和 21 题。
     - 所以约 1 分的改进，在一次完整重跑里测不出来。重放固定了检索和 JEV 的判断，才是测 View 规则的精确方法。
3. **用公式替代手调参数：两个版本都输给阶梯规则。** 公式是：只要"这一条正好是缺的那条"的概率 ≥ λ 就加进 View。λ = 0.01 事先由代价定下，不在基准上挑。

| 规则 | LoCoMo（对原 View） | LongMemEval（对原 View） | 对阶梯规则 |
|---|---|---|---|
| 阶梯规则 | 没把握的题 +21 / −7（p = 0.013），有把握的题不动 | +5 / −2 | — |
| 公式，JEV 原始分数 | 净 −4（p = 0.69） | 净 +2 | LoCoMo 净 −18（p = 0.025） |
| 公式，交叉校准后的分数 | 净 −5（p = 0.55） | 净 −12（p = 0.029） | LoCoMo −16（p = 0.044），LongMemEval −14（p = 0.009） |

4. **原因有两条，都指向同一个经验：JEV 的分数不能直接当概率连乘，它的是 / 否分界和排序更可靠。**
   - **原始分数没有校准。** 有把握的题里，JEV 给的低分偏高约 10 倍，公式误以为这些条目值得加，结果只加进了噪声；没把握的题里，公式又收得过早。
   - **校准的目标选错了。** 按"是标准证据的概率"校准后，那些不是标准证据、但能帮助作答的上下文条目被剪掉：有把握的题 View 从约 5 条缩到约 3 条，LongMemEval 时间推理题因此 0 / −7。
   - 有把握的题沿用的现行规则（入选线 0.4、填充 8 条、下限 0.1），在三种替代方案里都没有被超越。
5. **检索循环的公式化暂缓。** 它同样依赖"证据还缺的概率"：原始分数下，十几条 0.05 分的无关条目连乘，会把这个概率从 1 拉到 0.44 左右。已实现的 `worth` 循环模式保持默认关闭。量到的代价：
   - 多跑一轮约多花 5–7k JEV token，约 230 token 一条；
   - 改写搜索的成功率约 12–13%，翻页约 20–25%，都按 JEV 自己的判断计。
6. **全程没有在基准上挑参数。** 每一步都先登记再跑（补充 5–7）；View 的改动用重放检验：检索不变，同一批问题只换 View，逐题配对。
7. **简洁模式采纳（补充 10、11）：手调的数全部换成预算、JEV 自己的是 / 否和排序、以及上一步观察到的事件，准确率不变。**
   - 与 S6 同时完整重跑、逐题配对：LoCoMo 90.2 → 90.4，LongMemEval 91.0 → 90.4，合并差值 0.00（95% 区间 [−1.04, +1.04]），三条登记标准都满足。
   - 代价：每题费用约 1.22–1.23 倍，接近登记的 1.25 倍上限；延迟中位数 1.07–1.15 倍。
   - 留下的数只有预算（3 个需求、每页 20 条、候选池 48、3 轮、View 16 条）和 JEV 的 0.5，见文末附录。

## 2. 为什么阶梯规则有效

按排名看，每个位置上是标准证据的比例（LoCoMo）：

| JEV 排名 | 第 1 | 第 2 | 第 3 | 第 9–16 各位置 |
|---|---|---|---|---|
| JEV 有把握 | 87% | 15% | 6% | 约 0.4% |
| JEV 没把握 | 51% | 32% | 17% | 2–6% |

JEV 没把握时，它的分数都挤在很低的区间，靠分数分不出证据，但它的排序仍然有信息。所以把排名靠前的都交给回答模型；有把握时，证据几乎总在最前面，多给没有用。

- 这条规则用到的数：0.5 是 JEV 判断"需要 / 不需要"的分界，16 是 View 原有的条数上限。
- 去掉分数下限是关键。保留 0.1 的下限时，几乎没有效果（+6 / −5）。

## 3. 为什么公式版输了

在两个基准上，JEV 原始分数与实际命中率的对应（平均原始分 → 是标准证据的比例）：

| | 排名第 9 | 排名第 16 | 分数 0.05–0.1 | 分数 0.1–0.2 |
|---|---|---|---|---|
| LoCoMo 没把握 | 0.11 → 6% | 0.08 → 2% | 1.5% | 6.9% |
| LoCoMo 有把握 | 0.08 → 0.4% | 0.06 → 0.2% | 0.2% | 1.9% |

同一个分数，在有把握和没把握的题里含义差了 3–10 倍。

交叉校准本身是成功的，每条的对数损失：
- 在 LongMemEval 上拟合、用于 LoCoMo：0.138 → 0.094；
- 在 LoCoMo 上拟合、用于 LongMemEval：0.153 → 0.133。

但它校准的是"是否为标准证据"，而回答模型需要的不止标准证据，还需要上下文。

## 4. 实现

- **`unsureFill`**（提交 5e44d27b）：JEV 没有任何未被取代的条目达到 0.5 时，按排序填到这么多条，不设分数下限。测评脚本参数 `--unsure-fill`。有单元测试和集成测试；在 3 道 LongMemEval 题上的冒烟运行中，View 从 2、1、8 条放宽到 16 条。
- **`worth`**（提交 bb5c8d81、5e44d27b）：公式版的 View 规则和循环规则。默认关闭，代码注释中注明"不采纳"及原因。
- 全部 50 个策略测试通过。

| | LoCoMo | LongMemEval |

- **完整重跑的随机波动很大。** 规划、检索、JEV 和作答都会重新采样，同一套设置重跑一遍，在规则没有改动的题上也会翻转几十道。约 1 分的改进因此测不出来。
- **重放是测 View 规则的精确方法。** 它固定了检索和 JEV 的判断，只换 View。
- **结论：** 真实重跑没有推翻重放的结论，没有看到损害；LoCoMo 上方向一致。但它的完整流程收益很小，在一次重跑的波动之内。

## 附：不用大模型生成检索词的离线验证

**问题**：把用户问题分词、两两组合成检索词，或者用伪相关反馈扩展（从第一次检索排在前 10 的记录里，取"出现频率 × IDF"最高的词），能不能替代规划环节的大模型，省下约 1 秒？

**方法**：离线复刻混合检索的第一轮，不调用模型，只在本地计算查询向量。
- 每条检索词读一页（20 条 / 12,000 字），按 BM25 和向量分别排序，再用倒数排名融合。
- 各检索词的结果用 mixCues 合成候选池（≤ 48 条），统计含答案的记录进入候选池的比例。
- 大模型检索词取自 S4h-ds 运行的第一轮。

| 检索词来源 | LoCoMo（1,530 题） | LongMemEval（470 题） | 每题检索次数 |
|---|---|---|---|
| 大模型生成（现行） | 90.6% | 93.3% | 5 |
| 只用问题本身 | 79.3% | 85.8% | 1 |
| 问题 + 分词两两组合 | 85.3% | 85.0% | 13–17 |
| 问题 + 伪相关反馈 | 85.9% | 88.8% | 3 |
| 问题 + 组合 + 伪相关反馈 | 87.2% | 85.8% | 15–19 |
| 大模型生成 + 伪相关反馈 | 91.2% | 93.3% | 7 |
| 大模型生成 + 分词组合 | 88.5% | 88.9% | 17–21 |

**结论：**
- 不用大模型时，最好的方案比现行做法低 3.4 个百分点（LoCoMo）和 4.5 个百分点（LongMemEval）。差距集中在难题上：LoCoMo 多跳 −5.9、开放域 −10.1；LongMemEval 多会话 −6.5、时间推理 −5.3。
- 检索词越多，每条分到的候选池名额越少，宽泛的组合会挤掉好结果。
- 伪相关反馈是最好的无大模型方案，但叠加在大模型检索词上几乎没有增益。
- 这与 9 月 23 日的结论一致：让 JEV 从分词候选里挑检索词，在规模测试中比大模型给检索词低 17 个百分点。
- 规划环节保留大模型。降延迟应从合并规划调用、减少 JEV 往返、后台预备 View 入手。

## 附：快速模式（不调用规划大模型）的真实对照

**做法**（提交 e3e8f18c）：
- **数据源一侧**：记录类数据源检索时，可以顺带返回前 10 条命中共有、而在全库里少见的词（伪相关反馈，按全库词频计算）。
- **策略一侧**：`feedback` 打开后，先检索问题本身，再检索"问题 + 前 5 个扩展词"和"前 10 个扩展词"，全程不调用规划大模型。
  - 检索循环只剩一条需求，就是问题本身；问题带计数、列举类词语时，按"每个实例都要"处理。
  - 循环只翻页，不改写检索词。

**对照**：与 S6（用规划大模型，其余设置相同）在同一批题上同时运行，负载相同；DeepSeek 作答和判分。题目为 LongMemEval 按题型分层抽 230 题，LoCoMo 取 4 段完整对话共 583 题（题型比例与全集一致）。

| | LongMemEval，S6 | LongMemEval，快速 | LoCoMo，S6 | LoCoMo，快速 |
|---|---|---|---|---|
| 准确率 | 93.0% | 89.6%（+3 / −11，p = 0.057） | 90.7% | 89.0%（+15 / −25，p = 0.15） |
| 每题总耗时 p50 / p90 | 6.8 / 10.2 s | 5.3 / 7.9 s | 4.1 / 8.4 s | 3.0 / 7.8 s |
| 组 View p50 / p90 | 4.8 / 7.2 s | 3.3 / 4.9 s | 2.3 / 3.8 s | 1.3 / 2.0 s |
| JEV 每题 token / 调用次数 | 26.7k / 4.25 | 20.7k / 3.22 | 22.0k / 3.11 | 17.4k / 2.21 |
| 规划大模型每题 token | 418 | 0 | 322 | 0 |
| 证据进入 View | 82.2% | 79.5% | 89.2% | 85.5% |

**结论：**
- **更快、更省。** 组 View 的中位数时间少 1.0–1.5 秒（约 35–45%），每题总耗时少 1.1–1.5 秒（约 25%）；JEV 用量少约 22%，规划大模型的调用全部省掉。
- **准确率低 2–3 个百分点。** 损失集中在难题上：LongMemEval 时间推理 −12.5（+1 / −6）、多会话 −5.0；LoCoMo 多跳、开放域、单跳各约 −2。这与离线验证的预测一致，证据进入 View 的比例低了 3–4 个百分点。
- **适用场景。** 适合作为对延迟敏感、或不能调用大模型时的可选模式；默认仍用规划模式。
- **还能再快的地方。** LongMemEval 的快速模式里，组 View 仍要 3.3 秒，主要来自"每个实例都要"的题所跑的翻页轮次和 JEV 的多次往返。

## 附：四种组合（规划 / 快速 × 回答模型思考开 / 关）

回答模型关闭思考（`--no-thinking`，提交 d474e005）后，规划模式和快速模式各跑一组。题目与快速模式对照相同，同样是 4 组同时运行、每组并发 4 题；DeepSeek 判分。

| 规划 + 思考（默认） | 93.0% | 6.8 / 10.2 s | 4.8 s | 1.9 / 3.7 s |
| 快速 + 思考 | 89.6% | 5.3 / 7.9 s | 3.3 s | 1.7 / 3.5 s |
| 规划，不思考 | 84.8% | 7.2 / 11.4 s | 6.0 s | 1.2 / 2.1 s |
| 快速，不思考 | 82.2% | 5.6 / 7.9 s | 4.0 s | 1.3 / 2.1 s |

| LoCoMo（583 题） | 准确率 | 总耗时 p50 / p90 | 组 View p50 | 回答 p50 / p90 |
|---|---|---|---|---|
| 规划 + 思考（默认） | 90.7% | 4.1 / 8.4 s | 2.3 s | 1.4 / 4.6 s |
| 快速 + 思考 | 89.0% | 3.0 / 7.8 s | 1.3 s | 1.6 / 5.8 s |
| 规划，不思考 | 86.8% | 4.0 / 6.1 s | 3.0 s | 1.0 / 1.4 s |
| 快速，不思考 | 86.3% | 2.5 / 4.2 s | 1.5 s | 0.9 / 1.4 s |

逐题配对：

| | LongMemEval | LoCoMo |
|---|---|---|
| 关闭思考，规划模式 | −8.3（+4 / −23，p < 0.001） | −3.9（+13 / −36，p = 0.001） |
| 关闭思考，快速模式 | −7.4（+1 / −18，p < 0.001） | −2.7（+14 / −30，p = 0.023） |
| 快速对规划（都不思考） | −2.6（p = 0.39） | −0.5（p = 0.79） |
| 最快组合对默认 | −10.9（p < 0.001） | −4.5（p = 0.001） |

**结论：**
- **思考对准确率的贡献，大于规划大模型。** 关闭思考，LongMemEval 低 7–8 分，LoCoMo 低 3–4 分，都显著；规划模式对快速模式只多 2–3 分。
  - 损失最大的是需要推理的题：LongMemEval 多会话 87.5 → 72.5、时间推理 90.0 → 75.0、知识更新 92.5 → 82.5；LoCoMo 时间 86.0 → 80.2、单跳 95.5 → 90.4。
- **思考主要拖慢长尾，中位数影响不大。** 回答环节 p50 只少 0.4–0.7 秒，p90 少得多：LongMemEval 3.7 → 2.1 秒，LoCoMo 4.6 → 1.4 秒。
- **关闭思考的两组，组 View 反而更慢**（LongMemEval 规划 4.8 → 6.0 秒）。组 View 与回答模型无关，这是负载造成的：回答变快后，同一时刻停在检索阶段的题更多，JEV 和规划调用排队更久。所以两次运行之间的总耗时不能直接相减。
  - 按"思考那一轮的组 View + 不思考那一轮的回答"估算，关闭思考后每题中位数约省 0.5–0.8 秒。
- **取舍：** 默认组合准确率最高；"快速 + 思考"在延迟和准确率之间最划算。关闭思考省的时间主要在长尾，代价是 4–8 分，不建议作为默认。
- **与论文比较时要注意：** 已发表的系统大多用不带思考的 gpt-4.1-mini 作答。我们不开思考时，这两个子集上是 84.8%（LongMemEval）和 86.8%（LoCoMo），明显低于开思考时的 90 分以上。

## 附：简洁模式（补充 10、11）

**做法。** 去掉 View 规则和 JevAgent 循环里十几个经验手定的数和规则，只留下三类依据：

- JEV 的是 / 否判断，0.5 是它自己的分界线；
- JEV 的排序，加上系统预算；
- 上一步观察到的事件。

实现为开关 `--simple`（配置 `simple`，提交 06d6f4e0），默认关闭。

| 环节 | 规则 |
|---|---|
| View | JEV 判"需要"的进入；需要记忆时按 JEV 的排序补满预算（16 条），不设下限、不限来源；判"已过时"（0.5）的撤下 |
| 细判与需求表 | 只判可能进 View 的条目：筛选判"需要"的，加筛选排序前 16 条 |
| 单点需求 | 有"是"就满足 |
| 汇总需求 | 规划模型标 ALL，或已有 2 条不同记录判"是"；上一轮有新的"是"就沿这些检索翻页，没有就结束 |
| 还没有"是"的需求 | 翻排第一的线索所在检索的下一页；翻页没改进就换说法；两种都没改进就放弃 |

**结果。** DeepSeek 作答、规划和判分，两组同时运行，逐题配对。

| | LoCoMo（1,537 题） | LongMemEval（500 题） |
|---|---|---|
| S6 | 90.2 | 91.0 |
| 简洁模式 | 90.4 | 90.4 |
| 配对差 | +0.2（+45 / −42，p = 0.83） | −0.6（+13 / −16，p = 0.71） |
| 同一 S6 两次运行之差 | +0.7 | +1.0 |
| 每题费用 | $0.00146 → $0.00179（1.23 倍） | $0.00159 → $0.00194（1.22 倍） |
| 延迟中位数 | 3.9 → 4.5 秒 | 6.2 → 6.6 秒 |
| View 条数 | 7.2 → 15.9 | 6.7 → 15.7 |
| 证据全在 View 里 | 84.6% → 87.3% | 77.0% → 81.3% |
| 平均循环轮数 | 0.25 → 1.12 | 0.65 → 1.41 |

- **准确率完全持平。** 合并 2,037 题，差值 0.00，95% 区间 [−1.04, +1.04]，满足登记的非劣效标准（下限高于 −2）。View 重放给出 +0.6（p = 0.27），方向一致，也在波动内。
- **证据多了，准确率没跟着涨。** 证据齐全时两组准确率相同，多进来的证据集中在难题上，同时 View 也更长。
- **多出的费用来自两处：**
  - 回答模型每题多读约 1.5k token；
  - 汇总需求几乎全靠观察规则识别。规划模型自己标 ALL 的只有 5 个（LoCoMo）和 14 个（LongMemEval），按"至少 2 条判是"转为汇总的有 925 个和 553 个。同一个事实被多条记录重复提到时，这条规则也会触发，循环因此多翻页。
- **下一步。** 这条观察规则可以让它多依据一个观察信号，以降低费用。按登记要求，先登记，再在重放或新数据上检验，不在这批结果上直接调整。
